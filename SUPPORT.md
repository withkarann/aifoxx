# Support

Where to go, depending on what you need.

## I run a tool that is listed here

| What you want | Where to go |
|---|---|
| A fact is wrong or out of date | [Data correction](https://github.com/withkarann/aifoxx/issues/new?template=data-correction.yml) |
| Take my tool down | [Tool removal](https://github.com/withkarann/aifoxx/issues/new?template=tool-removal.yml) |
| We moved domain or changed name | [Data correction](https://github.com/withkarann/aifoxx/issues/new?template=data-correction.yml), and say what changed |
| A compliance claim is wrong | [Data correction](https://github.com/withkarann/aifoxx/issues/new?template=data-correction.yml), with a link on your own domain |

You do not need to explain yourself to have your own product removed. Ask, and it goes.

Corrections need a source URL on your own domain. That is not bureaucracy: it is the only reason anyone should trust what this directory says about you. A claim with a link behind it can be checked by a reader. A claim without one is just an assertion.

## I want to add a tool

Open a [tool submission](https://github.com/withkarann/aifoxx/issues/new?template=tool-submission.yml). Read [what we list](README.md#what-we-list) first, since some categories are out of scope and it saves you the trip.

Every submission is opened in a browser and checked against the live site before it goes in. Expect that to take a few days.

## Something on the site is broken

Open a [bug report](https://github.com/withkarann/aifoxx/issues/new?template=bug-report.yml). Include the page URL and what you expected to see.

## I have a question or an idea

Use [Discussions](https://github.com/withkarann/aifoxx/discussions). Questions asked there stay findable for the next person, which issues do not.

## I found a security problem

Do not open a public issue. Follow [SECURITY.md](SECURITY.md).

## I want to contribute code or data

Start with [CONTRIBUTING.md](CONTRIBUTING.md). It covers local setup and the checks that run before a pull request can merge.

## What to expect

This is maintained by two people alongside other work, so response times vary. Issues are read. Not every request is accepted, and when one is declined you get the reason rather than silence.

Removal requests from tool owners are the exception to any queue. Those are handled first.
